# 나스닥 방향성 일일 알림 — 설계 문서

작성일: 2026-11-23

## 1. 의도와 배경

매일 정해진 시간에 나스닥 지수의 방향성(상승/횡보/하락)을 **단기·중기·장기** 별로 수치화해서 카카오톡으로 받는다.
근거는 단순 뉴스 요약이 아니라 **시장 상태(추세·모멘텀), 투자자 심리, 지정학적 리스크, 매크로** 지표다.
1단계는 규칙 기반 수치 모델만 만들고, 2단계에서 AI(Claude)가 요약을 쓰고 지정학·뉴스 요소를 제한된 범위에서 조정하는 혼합형으로 확장한다.

## 2. 목표 / 비목표 / 반목표

**목표**
- 매일 자동 실행 → 데이터 수집 → 점수 계산 → 카카오톡 '나에게 보내기' 발송
- 기간별 점수(-100~+100)와 상승/횡보/하락 확률 제시
- 점수가 과거에 실제로 맞았는지 확인할 수 있는 백테스트 기능
- 매일의 점수와 입력 지표를 기록으로 남겨 추후 검증·튜닝에 사용
- 2단계(AI 혼합형)를 붙이기 쉬운 구조

**비목표 (1단계)**
- 자동 매매, 개별 종목 분석
- 뉴스 수집/분석, AI 호출
- 웹 대시보드

**반목표 (이렇게 되면 실패)**
- 검증되지 않은 숫자를 정밀한 예측처럼 보여주는 것 → 확률은 백테스트에서 나온 값으로만 표시
- 데이터 소스가 깨졌는데 조용히 오래된/빈 데이터로 점수를 내는 것 → 누락·지연 지표는 메시지에 명시
- 실행이 실패했는데 아무 알림이 없는 것 → 실패 시에도 오류 메시지 발송

## 3. 제약

- 언어: Python 3.11+
- 실행: 1단계는 로컬 Windows PC(작업 스케줄러), 이후 GitHub Actions로 이전. 코드는 실행 환경에 의존하지 않도록 작성(경로·비밀값은 설정/환경변수로).
- 데이터: 무료 소스만 사용. FRED API 키(무료) 필요.
- 전송: 카카오 REST API '나에게 보내기'(talk_memo). 카카오 개발자 앱 등록 필요.

## 4. 접근 방식 (검토한 대안)

| 방식 | 장점 | 단점 |
|---|---|---|
| **1. 규칙 기반 수치 모델 (선택)** | 무료, 재현 가능, 백테스트 가능 | 지정학 등 정성적 요소에 약함 |
| 2. AI 단독 판단 | 맥락 해석 우수 | 일관성 낮음, 검증 불가, API 비용 |
| 3. 혼합형 | 안정성 + 해석력 | 구현량 많음 |

사용자 결정: **1번으로 시작, 추후 3번(혼합형)으로 확장.**
따라서 점수 계산은 "지표 → 신호 → 카테고리 점수 → 기간별 합산"의 단계가 분리되어 있어야 하고, 2단계에서 "AI 조정값(±N점, 상한 있음)"을 마지막 합산 단계에 끼워 넣을 수 있어야 한다.

## 5. 사용자가 정한 것

- 전송 채널: 카카오톡 '나에게 보내기'
- 실행: 로컬 PC 테스트 → 클라우드 전환
- 점수 방식: 규칙 기반 먼저, 혼합형은 나중에
- 발송 시각: 매일 09:00 KST

## 6. 설계

### 6.1 구성

```
trade/
  config.yaml          # 지표 목록, 가중치, 임계값, 발송 설정
  .env                 # FRED_API_KEY, KAKAO_REST_API_KEY 등 (커밋 금지)
  nasdaq_signal/
    data/              # 소스별 수집기 (yfinance, FRED, Fear&Greed, GPR)
    indicators.py      # 원지표 → 신호값 [-1, +1]
    scoring.py         # 카테고리/기간별 점수 합산, 확률 변환
    backtest.py        # 과거 점수 재계산 및 적중률 평가
    message.py         # 카카오 메시지 포맷
    kakao.py           # 토큰 관리 + 발송
    main.py            # 일일 실행 진입점
  state/
    kakao_tokens.json  # 액세스/리프레시 토큰 (커밋 금지)
    history.csv        # 매일의 지표값·점수 기록
```

### 6.2 지표 (초안 — 빌더가 데이터 가용성 확인 후 조정 가능)

| 카테고리 | 지표 | 소스 |
|---|---|---|
| 시장 상태 | 나스닥100 대비 50일/200일 이동평균 위치, 20일·60일 수익률, 52주 고점 대비 낙폭, 시장 폭(RSP/SPY 상대강도) | yfinance (^NDX, QQQ, RSP, SPY) |
| 심리 | VIX 수준, VIX 기간구조(VIX/VIX3M), CNN Fear & Greed | yfinance (^VIX, ^VIX3M), CNN 비공식 엔드포인트(선택) |
| 지정학 | GPR 지수(Caldara-Iacoviello, 월간/일간), 금·유가 급변 | GPR 공개 파일, yfinance (GC=F, CL=F) |
| 매크로 | 10년 금리 변화, 장단기 금리차(T10Y2Y), 하이일드 스프레드, 달러지수, 금융여건지수(NFCI), 삼 법칙 경기침체 지표 | FRED, yfinance (DX-Y.NYB) |

- 심리 지표는 극단에서 **역발상**으로 처리(극단적 공포 = 중기 상승 신호, 극단적 탐욕 = 단기 경계).
- 선택(optional) 지표는 실패해도 전체 실행이 멈추지 않는다.

### 6.3 점수 계산

1. 각 지표를 신호값 [-1, +1]로 변환. 기본은 과거 N년(기본 5년) 대비 백분위 기반, 일부는 규칙 임계값(예: 200일선 위/아래).
2. 카테고리 점수 = 카테고리 내 지표 신호의 가중 평균.
3. 기간별 점수 = 카테고리 점수 × 기간별 가중치 행렬 → ×100 하여 -100~+100.
   - 예시 경향: 단기는 시장 상태·심리 비중↑, 장기는 매크로 비중↑. 구체 가중치는 `config.yaml`에 두고 백테스트로 조정.
4. 누락 지표는 제외하고 나머지 가중치를 재정규화. 누락 비중이 큰 경우 메시지에 "신뢰도 낮음" 표시.
5. 확률: 백테스트에서 점수 구간별로 실제 상승/횡보/하락 비율을 집계한 표(보정표)를 만들어, 오늘 점수가 속한 구간의 비율을 표시. 보정표가 아직 없으면 확률은 표시하지 않는다.
6. 2단계 확장 지점: 기간별 점수에 `ai_adjustment`(기본 0, 상한 ±10)를 더하는 자리를 남겨둔다.

**기간 정의와 라벨 기준 (기본값, config로 변경 가능)**

| 기간 | 미래 수익률 기간 | 상승 | 하락 | 그 사이 |
|---|---|---|---|---|
| 단기 | 10거래일 | > +1.5% | < -1.5% | 횡보 |
| 중기 | 63거래일 | > +4% | < -4% | 횡보 |
| 장기 | 252거래일 | > +8% | < -8% | 횡보 |

### 6.4 백테스트

- 과거 데이터로 일별 점수를 재계산(해당 시점에 알 수 있었던 데이터만 사용 — 미래 데이터 누출 금지. FRED 지표의 발표 지연도 고려).
- 출력: 기간별 방향 적중률, 점수 구간별 실제 결과 분포(= 확률 보정표), 점수와 미래 수익률의 상관.
- 히스토리가 짧은 지표(예: Fear & Greed)는 백테스트에서 제외하거나 가용 기간만 사용하고 그 사실을 리포트에 명시.
- 명령: `python -m nasdaq_signal.backtest` → 콘솔 요약 + 보정표 파일 저장.

### 6.5 카카오톡 전송

- 최초 1회: 로컬 스크립트로 카카오 로그인(인가 코드) → 액세스/리프레시 토큰 발급 → `state/kakao_tokens.json` 저장.
- 매 실행 시 리프레시 토큰으로 액세스 토큰 갱신. 카카오가 새 리프레시 토큰을 주면 저장.
- 리프레시 토큰 만료가 임박하면 메시지 하단에 "재인증 필요" 경고.
- 클라우드 전환 시 토큰 저장 위치 문제(갱신된 리프레시 토큰을 GitHub Secrets에 다시 써야 함)는 전환 단계에서 해결한다. 1단계 코드는 토큰 저장소를 교체 가능한 인터페이스로 둔다.

### 6.6 메시지 형식 (예시)

```
[나스닥 방향성] 11/24 (월) 마감 기준
단기 ▲ +32  상승55 횡보30 하락15
중기 ─ +5   상승38 횡보40 하락22
장기 ▲ +41  상승62 횡보23 하락15

시장상태 +0.4 | 심리 +0.1 (탐욕 72)
지정학 -0.2 | 매크로 +0.3
주요: VIX 14.2, 10년물 4.21%(-8bp), HY 스프레드 3.1%
⚠ 누락: Fear&Greed
```
- 화살표: +20 이상 ▲, -20 이하 ▼, 그 사이 ─ (config로 변경 가능)
- 카카오 텍스트 메시지 길이 제한(200자 내외 미리보기, 본문 최대 길이) 안에 들어가도록 한다.

### 6.7 실행 일정

- 발송 시각: 매일 09:00 KST (사용자 지정, 미국장 마감 데이터 반영 후)
- 로컬: Windows 작업 스케줄러에 `python -m nasdaq_signal.main` 등록
- **매일 발송 (주말·휴장일 포함, 사용자 결정)**
- 주말/휴장일에는 그날 실제로 갱신된 데이터만 새로 반영하고, 나머지는 직전 거래일 값을 쓴다. 메시지에 "휴장 — 시장 데이터 ○/○ 기준"과 갱신된 항목을 표시.
  - 일요일: 지정학(GPR 일간, 금/유가 선물은 휴장) 등 주말에도 갱신되는 소스만 반영
  - 월요일 09:00 KST: 나스닥100 선물(NQ=F)이 열려 있으므로(일요일 18:00 ET 개장) 선물 등락률을 참고값으로 표시. 1단계에서는 점수에 넣지 않음(백테스트 기준과 맞추기 위해).

### 6.8 실패 처리와 기록

- 각 실행 결과(지표 원값, 신호값, 점수, 누락 목록)를 `state/history.csv`에 추가.
- 핵심 데이터(나스닥 가격) 수집 실패 시 점수 대신 오류 메시지를 카카오로 발송.
- 로그 파일은 `state/logs/`에 일자별.
- `--dry-run` 옵션: 발송 없이 콘솔 출력만.

## 6.9 검토 후 확정한 사항 (설계자 판단 — 사용자 확인 대상)

1. **가중치 튜닝과 확률 검증**: 가중치는 `config.yaml`에서 사람이 수동 조정(자동 최적화 없음). 백테스트는 기간을 학습 구간(예: ~2017)과 검증 구간(2018~)으로 나누어 둘을 따로 보고하고, **확률 보정표는 검증 구간 결과로만** 만든다. 이후 워크포워드 방식은 필요 시 추가.
2. **히스토리가 짧은 지표**: 점수에는 백테스트 가능한 핵심 지표만 사용. Fear & Greed처럼 히스토리가 짧은 지표는 1단계에서 메시지에 **참고값으로만** 표시하고 점수에는 넣지 않는다. 이렇게 해야 실시간 점수와 보정표의 구성이 일치한다. VIX3M·RSP 등은 가용 기간이 백테스트 시작점을 결정하므로, 빌더가 시작 연도를 정하고 문서화한다.
3. **시점 데이터(누출 방지)**: FRED 지표는 발표 지연만큼 시프트해서 사용(수정치 사용은 감수하고 한계로 명시). ALFRED 빈티지 데이터는 추후 과제.
4. **2차 알림 채널**: 1단계에는 두지 않음. 리프레시 토큰 만료 2주 전부터 메시지에 재인증 경고, 실패는 로컬 로그에 기록. 클라우드 전환 후에는 GitHub Actions 실패 알림(이메일)으로 보완.
5. **메시지 길이**: 카카오 텍스트 템플릿 제한(200자)에 맞추기 위해 **두 개의 메시지로 분할**: ① 기간별 점수·확률 요약, ② 카테고리 점수·주요 지표·경고. 각각 200자 이내.
6. **기간별로 다른 신호**: 지표는 기간별로 다른 신호값을 가질 수 있다(지표 × 기간). 기본은 동일 변환이고, 심리 지표 등은 기간별 변환을 따로 정의한다(예: 극단적 탐욕 → 단기 -, 장기 영향 작음).

## 6.10 재튜닝 (2026-11-23, 사용자 승인: 방향 재설정안)

- 첫 백테스트에서 모든 기간 점수-수익률 상관이 음수(추세 지표가 평균회귀, 공포 후 반등)로 나와 방향을 데이터로 재설정.
- 규칙: 학습 구간(2010~2017)을 앞/뒤 절반으로 나눠 두 절반 모두 |IC| ≥ 0.03이고 부호가 같을 때만 사용, 음수면 방향 반전, 그 외 해당 기간에서 제외. 검증 구간(2018~)은 선택에 쓰지 않음. 결과는 `tuning.yaml`(`python -m nasdaq_signal.tune`).
- 하이일드 스프레드(FRED, 최근 3년치만 제공)는 점수에서 빼고 표시 전용으로, 점수에는 HYG/IEF 60일 변화(`credit`)를 사용.
- 확률표가 유효하면 화살표 = 가장 가능성 높은 결과(동률은 횡보). 점수 숫자는 '평소 대비 우호도'.
- 검증 구간 결과(재튜닝 후): 순위상관 단기 +0.12, 중기 +0.35, 장기 +0.51 (재튜닝 전 -0.10/-0.14/-0.16).

- 재튜닝 2차 (2026-11-23, 사용자 승인): 삼 법칙·금융여건지수 점수 제외(2008년 위기 내내 강한 매수 신호/위기 구간 역작동), 학습 구간을 2005~2017로 확장(금융위기 포함).
  그 결과 장기는 검증 구간에서 안정적 예측 지표가 없어(상관 -0.30) 예측을 끄고 역사적 기본 비율(2005~, 상승 71/횡보 20/하락 9)만 표시. `horizons.long.predict: false`.
  검증 구간 상관: 단기 +0.13, 중기 +0.20.

## 7. 빌더 재량
